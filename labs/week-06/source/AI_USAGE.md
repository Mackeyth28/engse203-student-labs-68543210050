# AI_USAGE — LAB 06

บันทึกการใช้ AI ระหว่างทำงาน · **ใช้ AI ได้ แต่ต้องเป็นเจ้าของโค้ดที่ส่ง**

> ผู้สอนจะสุ่มถามจากโค้ดที่ส่ง หากอธิบายไม่ได้ คะแนนส่วนนั้นจะถูกทบทวน

---

## ครั้งที่ 1

**ถามอะไร**

ถาม Microsoft Copilot เกี่ยวกับการทำ CP07 ว่าต้องเขียน `notFound` และ `errorHandler` อย่างไร รวมถึงต้องเพิ่ม Middleware ทั้งสองตัวไว้ตรงส่วนใดของ `app.js`

**AI ตอบว่าอย่างไร (สรุปสั้น)**

AI แนะนำให้ `notFound` ตอบสถานะ `404` เป็น JSON พร้อมบอก Method และ Path ที่หาไม่พบ ส่วน `errorHandler` ต้องมีพารามิเตอร์ 4 ตัว ได้แก่ `err`, `req`, `res` และ `next` เพื่อให้ Express ระบุได้ว่าเป็น Error-handling Middleware นอกจากนี้ต้องติดตั้ง `notFound` หลัง Route ทั้งหมด และติดตั้ง `errorHandler` เป็น Middleware ตัวสุดท้าย

**ใช้ส่วนไหน / แก้เองตรงไหน**

นำคำแนะนำมาใช้แก้ไฟล์ `src/middleware/errorHandler.js` โดยเขียนฟังก์ชัน `notFound` และ `errorHandler` จากนั้นเพิ่ม `app.use(notFound)` และ `app.use(errorHandler)` ใน `src/app.js` โดยวางไว้หลัง `requestRoutes` ผู้จัดทำตรวจสอบลำดับ Middleware และทดสอบด้วย Postman ด้วยตนเอง

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 2

**ถามอะไร**

ถาม Microsoft Copilot เกี่ยวกับ CP08 ว่าทำไมคำร้องที่เพิ่มด้วย POST จึงหายหลังจากปิดและเปิดเซิร์ฟเวอร์ใหม่ และต้องแก้ `requestService.js` อย่างไรเพื่อให้ข้อมูลอยู่ถาวร

**AI ตอบว่าอย่างไร (สรุปสั้น)**

AI อธิบายว่าข้อมูลเดิมถูกเก็บอยู่ในตัวแปร `requests` ภายในหน่วยความจำเท่านั้น เมื่อปิดเซิร์ฟเวอร์ข้อมูลจึงหาย วิธีแก้คือใช้ `readFile` และ `writeFile` เพื่ออ่านและเขียนข้อมูลใน `data/requests.json` เพิ่มฟังก์ชัน `persist()` และเรียกใช้หลังการเพิ่มหรือลบข้อมูล ส่วน `loadSeed()` ต้องพยายามอ่าน `requests.json` ก่อน หากยังไม่มีไฟล์จึงโหลด `initialRequests.json`

**ใช้ส่วนไหน / แก้เองตรงไหน**

นำคำแนะนำมาใช้เพิ่ม `DATA_PATH` และฟังก์ชัน `persist()` ใน `src/services/requestService.js` เปลี่ยน `create()` และ `remove()` ให้เป็นฟังก์ชัน `async` พร้อมเรียก `await persist()` หลังข้อมูลเปลี่ยน และแก้ Controller ให้ใช้ `async/await` เมื่อติดต่อกับ Service นอกจากนี้เพิ่ม `data/requests.json` ลงใน `.gitignore` ผู้จัดทำทดสอบด้วย Postman โดยเพิ่มคำร้องใหม่ ปิดเซิร์ฟเวอร์ เปิดใหม่ และตรวจพบว่าคำร้องเดิมยังอยู่

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## สรุป

- ส่วนที่เขียนเองทั้งหมด: การประกาศ Route สำหรับ GET, POST และ DELETE การทดสอบ API ด้วย Postman การบันทึกผลจริงใน `API_TEST.md` การตรวจ Status Code และการจัดเก็บ Screenshot หลักฐาน
- ส่วนที่ AI ช่วย: วิเคราะห์โครงสร้าง Route, Controller และ Service อธิบายการติดตั้ง `notFound` และ `errorHandler` รวมถึงอธิบายการใช้ `readFile`, `writeFile`, `persist()`, `async` และ `await` สำหรับจัดเก็บข้อมูลลงไฟล์ JSON
- ส่วนที่ยังไม่มั่นใจ: การเขียน Error Handling สำหรับกรณีซับซ้อน และการจัดเก็บข้อมูลพร้อมกันจากคำขอหลายรายการ ซึ่งต้องศึกษาเพิ่มเติม
