# ทางเลือกฐานข้อมูล

## 1. ทำไมโปรเจกต์นี้เลือก SQLite แทน MongoDB

โปรเจกต์นี้เลือก SQLite เพราะข้อมูลคำร้องมีโครงสร้างชัดเจน และมีความสัมพันธ์ระหว่างตาราง `users` กับ `requests` ผ่าน `requester_id` ฐานข้อมูลเชิงสัมพันธ์จึงเหมาะกับการกำหนด Primary Key, Foreign Key, UNIQUE และ CHECK Constraint เพื่อป้องกันข้อมูลผิดรูปแบบ ระบบมีขนาดไม่ใหญ่มาก จึงยังไม่จำเป็นต้องเปิด Database Server แยก นอกจากนี้ SQLite จัดเก็บเป็นไฟล์ ทำให้ติดตั้ง ทดสอบ และสำรองข้อมูลได้ง่าย

## 2. ถ้าเปลี่ยนไป MongoDB จะกระทบชั้นไหนบ้าง

ชั้นที่ได้รับผลกระทบโดยตรงคือ Service Layer เพราะต้องเปลี่ยนคำสั่ง SQL และ `node:sqlite` ไปเป็น MongoDB Driver หรือ ODM เช่น Mongoose รูปแบบการเชื่อมความสัมพันธ์ระหว่างผู้ใช้กับคำร้องจะเปลี่ยนจาก JOIN เป็นการอ้างอิง Document หรือฝังข้อมูล ส่วน Controller ก็ต้องแก้เป็นฟังก์ชัน `async` และใช้ `await` เมื่อเรียก Service เพราะการติดต่อ MongoDB ผ่านเครือข่ายคืนค่าเป็น Promise อย่างไรก็ตาม Route และ Frontend สามารถคงรูปแบบเดิมได้ หาก Endpoint, HTTP Status และชื่อ Field ใน API Contract ไม่เปลี่ยน

## 3. Async จำเป็นเมื่อไร และไม่จำเป็นเมื่อไร

Async จำเป็นเมื่อโปรแกรมต้องรอการทำงานภายนอก เช่น การเรียก API การอ่านไฟล์แบบไม่บล็อก หรือการติดต่อฐานข้อมูลที่อยู่คนละเครื่องผ่านเครือข่าย การใช้ `async` และ `await` ช่วยให้ Node.js รับ Request อื่นต่อได้ระหว่างรอผลลัพธ์ แต่ `DatabaseSync` ของ SQLite ในโปรเจกต์นี้ทำงานกับไฟล์ในเครื่องแบบ Synchronous จึงไม่จำเป็นต้องทำให้ทุก Query เป็น Async หากเปลี่ยนไปใช้ MongoDB หรือฐานข้อมูล Cloud ที่คืนค่าเป็น Promise ทั้ง Service และ Controller จะต้องรองรับ Async ด้วย
